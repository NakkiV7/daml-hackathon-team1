Limits enforced by the ledger, not by an API.

An AI agent holds a mandate: a total budget, a daily budget, one approved supplier, an expiry, and revocation the agent cannot block. Every limit is a rule inside a Daml contract, so it holds for anyone reaching the ledger — including something that bypasses this application entirely.

Settlement

authorisation and settlement are separate

The mandate decides whether the agent may spend, on the ledger. Moving the Canton Coin is a second step: a token-standard transfer needs disclosed contracts fetched from the registry for that one transaction, which a Daml choice body cannot go and get. An unauthorised charge never reaches it.

09

What is real, and what is not

Live on Canton DevNet

  • The mandate is a real contract with a real contract id
  • Cap, period cap, allow-list, expiry and revocation are enforced by Mandate.daml
  • Every refusal is an AssertionFailed returned by Canton
  • Charge and revoke audit records are contracts on the ledger
  • Canton Coin really moves; the payee's balance changes
  • Killing this backend loses nothing — the state was never ours

Not done

  • Settlement moves 0.1 at a time; the agent holds about 5 coin
  • The authorisation cap is 500 while the balance is 5, so the cap is proven by refusal rather than by exhaustion
  • The allow-list is fixed when the mandate is granted
  • Period windows roll forward on the next charge, not on a timer — nothing in Daml runs on a schedule
